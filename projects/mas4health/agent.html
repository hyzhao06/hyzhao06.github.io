ScienceBuddy

ScienceBuddy 把对话、工具调用、执行记录和分析结果放在同一个任务中。主机负责控制工具权限、调用预算和验证流程，Agent 根据每次调用返回的内容决定下一步。

公开仓库中的 Simple-SciBuddy 将 harness、execution broker、verifier 和训练接口分开。原始返回值、整理后的回答、执行轨迹和产物也分别保存，因此一次任务可以回看和复查。

仓库提供的是研究实现，不包含 ScienceBuddy 完整产品的后端代码。

MAS4Health Agent

MAS4Health 沿用了 host-owned loop：主机负责执行、预算、失败状态和停止条件，模型工具与上层决策彼此分开，原始 observation、trajectory 和 artifacts 都会留在 trace 中。

AgentRequest 用数据集、病例、模态、目标和提示词描述一次请求。Router 按这些字段排除不兼容的模型，再使用已经完成的基准结果排序。模型候选完全由结构化规则产生；Runtime 也只执行注册表中预先定义的 argv。

选定工具后，Runtime 通过 JSON 子进程调用原有 baseline。推理过程不能读取 ground truth；返回的 NIfTI 需要通过几何、文件大小和 SHA-256 校验，成功或失败都会写入 trace。CLI 和 MCP 共用同一套 AgentLoop。
