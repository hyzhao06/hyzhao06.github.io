01 / 参考

ScienceBuddy 如何组织科学 Agent

它把“怎样做事”放在 host-owned harness 中：主机控制工具、预算、执行与验证，Agent 在观察结果后继续决策。研究版本还交替优化 harness 与任务模型，形成双重递归。

参考执行骨架

ScienceBuddy 的工作区把对话、科学工具、执行记录和分析产物放在同一任务上下文中。公开仓库中的 Simple-SciBuddy 进一步把 harness、execution broker、verifier 与训练适配层分开。

我们沿用三点：host 掌握执行权；原始 observation 和最终回答分开保存；trajectory 与 artifact 随时可以检查。

公开代码是简化研究实现，不包含完整产品后端，因此这里不声称复刻其产品。

02 / 实现

面向医学影像的改造

我们保留可控执行与可检查轨迹，同时收紧工具边界：请求必须结构化，路由必须可解释，输出必须通过 NIfTI 与哈希校验。

沿用 FROM SCIENCEBUDDY

  • ✓Host-owned loop：route → act → observe → stop
  • ✓工具执行与上层决策分离
  • ✓保留原始 observation、trajectory 与 artifacts
  • ✓预算、失败和停止原因由 host 明确控制

改造 FOR MEDICAL IMAGING

  • →确定性 capability router，不让 LLM 凭模型名猜路由
  • →只执行注册表 argv，禁止任意 shell / Python
  • →推理阶段隔离 ground truth，并强制记录 false
  • →复用冻结 baseline，校验几何、字节数与 SHA-256
